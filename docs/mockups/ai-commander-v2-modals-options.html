1 · Modal system three tiers, three shapes, three keyboard contracts

The point isn't the color — it's that your hands can't do the wrong thing. Each tier changes the border, the default button, and what Enter/Esc do. A danger modal never has an Enter default.

the other three shapes

  • input — info frame with one field: rename, mkdir, new session name, git commit message. Enter submits, Esc cancels.
  • pick — info frame with a filterable list: open recent folder, switch model, choose session, choose viewer. Same component as the + picker.
  • progress — info frame with a bar and Esc = cancel: upload, compact, cad render, comfyui job. Turns into a toast when done.
Rules that make the tiers legible without reading: red never shares a frame with amber; a double border only ever means "someone can lose something"; the letter shortcuts are always shown next to the button; the safe button is always the one Esc maps to.

4 · Workspace state .aicommander/ layout — restore exactly where you were, like VS Code

.aicommander/
├── workspace.json        panels, tabs, gutter position, focused panel, open modals? no — last layout preset
├── config.json           project defaults: mode, loop limits, boot sequence, brain endpoint
├── rules.json            permission regexes (merged over ~/.aicommander/rules.json)
├── system.md             harness manual for the brain (copied from global on first open, editable)
├── sessions/
│   ├── index.sqlite      search, rewind index, token counts per group
│   └── 014/
│       ├── session.jsonl one event per line: user, brain, tool_call, tool_result, permission, cancel, compact
│       ├── meta.json     name, model, created, forked_from
│       └── img/
├── out/                  full tool outputs when over the cap (referenced by path from the log)
