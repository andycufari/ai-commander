harness — commander v1

Layout A, redrawn Ratatui-style: every region is a bordered block with its title cut into the frame, focus = bright border, the F-key bar reads what's under the cursor. Same palette as v0. Panels split by a draggable gutter (┊) that also answers Ctrl+←/→.

3 · Permission popup the NC dialog, doing something useful

Every shell call passes through a regex allow/deny list in .harness/rules.json (project) merged with a global one. A match opens this dialog and blocks the loop. Same dialog for git push, writes outside the repo, and network calls.

5 · What the brain sees system prompt is a file you can edit (F4)

Context is assembled in a fixed order every turn. Two layers are yours: the harness manual and the project boot. F4 opens either in the other panel as a plain md editor.

1 · harness manual .harness/system.md editable — how panels, mentions, open_in_panel, permissions and the sql tool work; the brain's UX contract 2 · project boot AGENTS.md or CLAUDE.md loaded from repo root if present BOOT.md · SOUL.md · rules/* optional, loaded in that order if present (file-organisation rules, voice, what never to touch) 3 · skills index skills/*/SKILL.md names + one-line descriptions only 4 · enabled tools core + whatever you # mentioned 5 · git state branch, dirty files, last 3 commits (cheap, refreshed each turn) 6 · session messages, with attached file/skill blocks placed above the turn that mentioned them compacted summary replaces old turns when you press F6
  • Projects can lock layer 2 with a .harness/config.json → "boot": ["AGENTS.md","SOUL.md","rules/"] so the sequence is explicit, not guessed.
  • Layer 1 is where the "self-improve" story lives: when the brain writes a new viewer into .harness/viewers/, it also appends a line to the manual describing it.

LayoutA · Commander. Two panels, resizable gutter, each panel hosts tabbed views.
Quick actionsContext-relative F-key bar. File manager = NC keys (F3 view, F4 edit, F5 copy, F6 move, F7 mkdir, F8 delete). Chat = session keys.

PermissionsRegex rules (global + project) on shell/git/network; NC double-border dialog; allow once / session / edit / deny.
SkillsAuto-discovered from skills/; index in system prompt; full content only when mentioned.
+ pickerOne picker, four tabs (@ / # !). Harness owns placement in context.
System prompt.harness/system.md, editable in-app, then project boot sequence (AGENTS/CLAUDE → BOOT/SOUL/rules), configurable.
LookRatatui blocks, titles in borders, bright border = focus. Palette: green-black / phosphor / amber for the brain.
